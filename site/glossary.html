Glossary

Plain-English definitions of every term used in this manual. Each entry
explains the idea once, briefly, with an example where it helps.

Agent (AI agent)

An AI assistant that can use tools — read files, search, run small
commands — rather than only chatting. See <a href="agent-help.html">agent help</a>.

Archive

The calm folder for anything finished or cold, organized by year:
20-archive/2026/. Nothing here needs attention; that is the point. One of
the <a href="the-four-corners.html">the four corners</a>.

Backlink

The reverse view of a wiki-link: "which notes point at this one?" Apps
like Obsidian and Zettlr show it automatically. Worth having, not worth
thirsting for — search does most of the same job.

Daily note (daily landing pad)

One file per day, 90-daily/2026-10-27.md, that catches everything that
arrives during the day. The first file you open, the last you close. See
<a href="the-four-corners.html">the four corners</a>.

Fleeting note

A raw thought in its own file, written in one breath, living in
00-inbox/ until the monthly tidy <a href="monthly-tidy.html">monthly tidy</a> promotes, attaches,
archives, or deletes it. Related: <a href="glossary.html#daily-note">daily note</a>.

Front matter

A small block of settings at the top of a Markdown file, wrapped in ---
lines, often used to record things like type or tags. Optional; plain text
works without it.

Hub note

A list-page that collects [[links]] on one life area (Work, Creations,
Learning). Handrails for tired days. See <a href="linking-ideas.html">linking ideas</a>.

Inbox (00-inbox/)

The standing pile of <a href="glossary.html#fleeting-note">fleeting note</a> files. Allowed to be messy by
design; kept a puddle, not a bog, by the monthly sweep.

ISO date

The YYYY-MM-DD date order (e.g., 2026-03-14) that sorts correctly
everywhere, forever. The only date format this manual uses. See
<a href="naming-that-survives-years.html">naming that survives years</a>.

Local-first

Software or storage where your files live on your device first, in
open formats you can open with any tool. The vault's core promise.

Markdown

A plain-text format where simple symbols mean simple structure: # before
a line makes a heading, - makes a bullet, **bold** makes bold, and
[[double brackets]] make wiki-links. Every manual chapter is a Markdown
file, and every one of them can be read raw as plain text.

MCP (Model Context Protocol)

A standard way for AI assistants to use small external tools ("servers")
safely — for example, a notes server that can search and read your vault.
See <a href="agent-help.html">agent help</a>.

MVP (minimum viable product)

The smallest version of a thing that still does its job. This manual's
method is deliberately MVP: four folders and one monthly timer.

Notes-mcp-server

A small local tool that gives an <a href="glossary.html#agent">agent</a> abilities like search_notes,
read_note, and move_note over your vault. Optional; see <a href="agent-help.html">agent help</a>.

Orphan note

A note with no [[links]] to or from anything. Not a sin — some notes are
just receipts. During the tidy, give orphans a link if you want them in the
web.

Plain text

Text with no hidden formatting — opens in any editor on any machine, from
1980 to after. The file types here are .md and .txt.

Project note

A note (or folder) for something active with an end in sight, living in
10-projects/, with the next action bolded at the top.

Second brain

A trusted external memory — a folder of plain files in your case — that
remember so you can think. The whole subject of this manual.

Vault

The one folder that contains your whole knowledge base. Any name works;
this manual's starter calls it my-second-brain/.

Wiki-link

A link between notes written as [[note-title]]. The honest little
workhorse of <a href="linking-ideas.html">linking ideas</a> — and of this manual's own pages.
